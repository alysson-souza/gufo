## Independent references

llama.cpp's graph and Recursive's SGLang/MLX model code. It decodes weights
with `core::quant`, keeps FP32 activations and K/V, and accumulates matmuls in
double. It is bit-identical across chunk sizes 1/5/64 and batch sizes 1/50.
Second implementation: llama.cpp `970b51ce` (Flint support from `a37cc461`,
ggml-org/llama.cpp#30928), ROCm and pure CPU (`--ngl 0`) backends, F16 KV.

## Tokenizer and template

`flint.tokenizer` checks 134 goldens generated by
`tools/flint/tokenizer_goldens.py` with HF `tokenizers` 0.23.3 from the source
`tokenizer.json`: code, prose, contractions, CJK/kana boundaries, digit runs,
whitespace, emoji, combining marks, every added token and invalid UTF-8
round trips. Unretained differential fuzzing (30,000 strings over a hard
alphabet, 30,000 over random code points) found 0 mismatches after pinning
Unicode 16 character classes (`tokenizers` uses Oniguruma's Unicode 16 tables;
host ICU is Unicode 17). llama.cpp `llama-tokenize` matches all 134 with
special tokens parsed; without parsing it still splits the 12 user-defined
tokens, so 14 cases differ there (HF is the authority).

`flint.chat_template` compares the compiled renderer with 14 goldens rendered
by jinja2 3.1.6 through transformers 4.57.1 `render_jinja_template`
(`tools/flint/chat_template_goldens.py`): system/developer roles, tools,
historical calls, tool responses and reasoning. Loading rejects a GGUF whose
template SHA-256 differs from the pinned `7940f4ff…`.

## Replay guarantees

Measured with the real model in `flint_session_test` and the operator tests:

- Decode operators are row-count invariant (`flint.batch_invariance_ops`), so
  batched serving rows equal serial execution bit for bit, widths 1–8.
- Prefill uses the matrix tier for every row count and split-invariant
  attention (`flint.split_invariance_ops`): chunks 37/512/513/514 and splits
  at 1, n/2, n−1 reproduce one-pass logits exactly; the long prompt at chunk
  512 and 2048 is byte-identical.
- Snapshots (RAM and serialized, fresh session, in-place rewind and
  mid-generation) restore bit-identical frontier logits; payload size equals
  `PayloadBytes()`; restore rejects foreign artifacts and versions.
- A cancelled prefill leaves position and logits unchanged and replays exactly.
- A cache hit is bit-identical to a cold run: after any Sync, K/V and logits
  depend only on the token sequence. Decode and prefill kernels round
  differently, so a Sync that extends generated tokens first evaluates them
  again through prefill from the last prefill-written position, restoring the
  sliding-window rows before it from a per-session anchor (36.7 MB) copied
  when decoding starts. Generation stays pure decode (tg1024 unchanged:
  Q8_0 59.4 tok/s, C4 52.4 per session); the extending turn prefills about one
  extra token per generated token. Checked bitwise on logits for 1, 511, 513,
  2,100 and 2,700 generated tokens (past the 2,575-slot ring), live,
  restored, after a cancelled re-prefill and after batched decode beside a
  different session; and through the server, where a reasoning-free
  follow-up to a 2,700-token reply reuses the previous prompt and matches a
  cold run. Before this, Q8_0 chose a different token at step 7 of a
  continued chat.

These are consistency checks within one build and configuration, not
independent accuracy evidence.

## Known limits

- **Routing near-ties.** Sigmoid scores for the sixth expert slot can differ in
  the third decimal between implementations (long position 116, layer 15:
  experts 59 vs 235). Different choices produce single-position KL spikes up
  to 23–33 in every implementation, including llama.cpp; each implementation
  has its own outliers.
- **Chat position 0.** `<|system|>` as the first token is ill-conditioned:
  llama.cpp HIP alone differs by KL 3.26 between batch-1 and batch-50
  evaluation. Including it, chat KL mean is 0.0436 (Gufo prefill), 0.0402
  (decode) and 0.0645 (llama.cpp HIP).
- **Prefill attention precision.** Prefill attention feeds q and P to WMMA as
  FP16 with FP32 accumulation and softmax (error ≤ about 4e-4·max|v| against
  FP64); decode stays near 1e-7. K/V are stored as FP16 in both modes, as in
  llama.cpp.
- **Activation range.** Q8_1 activations inherited from llama.cpp's MMQ/MMVQ
  require |value| < 8.3e6. Block sums are scaled by 2^-8 so routed Q4_K/Q5_K
  prefill no longer overflows FP16 at |Σ32| > 65504 (seen in layer 46).
- **Historical argument spelling.** Shared JSON serialization spells some
  numbers differently from Python's `json.dumps` (`1.0` → `1`, `1e5` →
  `100000`, `0.0001` → `1e-04`, `-0.0` → `-0`; integers above 2^53 lose
  precision). This affects replayed typed tool arguments and schemas; the
  template goldens avoid these spellings.
- **Reasoning.** The llama.cpp oracle puts `<think>` at p≈1 for the first
  assistant token on every prompt tried; the next candidate is e^-15 or lower.
  Suppressing `<think>` produced incoherent text, and a prefilled empty block
  leaked reasoning into content, so Gufo keeps the model's choice. For
  thinking-off requests the functional harness sends
  `reasoning_budget_tokens: 0`; the model often continues reasoning as content
  after the forced `</think>`.
- **Functional API selection** (`impact.py --model flint --tier pr`): 31 of 40
  suites pass; three harness failures pass on targeted reruns. Six model-behaviour
  failures remain: system-injection (`ALPHA.` for `ALPHA`), tool-agent-loop
  (repeats one read), tool-edges (writes a fake call block as text),
  tool-parameter-order, tool-reasoning (wrong edit call) and tool-schema-edges
  (`["1"]` for `[1]`); `tools` `auto_open_object` wraps open-object arguments.

## Reproduce

Build the test targets in the Nix development shell (see
[AGENTS.md](../../../AGENTS.md#focused-tests)):

```sh
nix develop -c cmake --preset gpu-test
nix develop -c cmake --build --preset gpu-test --target flint_tests flint_session_test \
  flint_gpu_probe flint_reference_probe
export GUFO_FLINT_MODEL=/path/to/flint-UD-Q4_K_XL.gguf
nix develop -c ctest --preset gpu-full -L flint --output-on-failure
build/gpu-test/tests/models/flint/flint_session_test
```

Matched-token comparison (`W` holds token files and dumps; `llama_logits` is
built from `tools/flint/llama_logits.cpp` inside the llama.cpp checkout):

```sh
uv run tools/flint/prompts.py --source /path/to/RecursiveSI-flint --out "$W"
for p in chat code long; do
  build/gpu-test/tests/models/flint/flint_reference_probe --model "$GUFO_FLINT_MODEL" \
    --tokens "$W/$p.ids" --dump "$W/$p.ref.f32"
  build/gpu-test/tests/models/flint/flint_gpu_probe --model "$GUFO_FLINT_MODEL" \
    --tokens "$W/$p.ids" --dump "$W/$p.prefill.f32"
  build/gpu-test/tests/models/flint/flint_gpu_probe --model "$GUFO_FLINT_MODEL" \
    --tokens "$W/$p.ids" --dump "$W/$p.decode.f32" --mode decode
  "$LLAMA_LOGITS" --model "$GUFO_FLINT_MODEL" --tokens "$W/$p.ids" --dump "$W/$p.llama.f32"
  uv run tools/flint/compare_logits.py --teacher "$W/$p.ref.f32" \
    --candidate "$W/$p.prefill.f32" --tokens "$W/$p.ids" --json "$W/$p.prefill.json"
done
```

`tools/flint/compare_taps.py` locates the first diverging layer from
`--taps` dumps of either probe and `llama_logits`. The CPU reference takes
about 1 s per token for short prompts and 0.24 s per token in 512-token chunks.

## Benchmark method

October 23, 2026, 01:14–01:33 UTC; refreshes 01:45–01:49 (multi-ar) and 01:51–02:05 UTC (single-ar). Host: Ryzen AI MAX+ 395 / Radeon 8060S
(gfx1151), 128 GB, Linux 7.3.0, ROCm development build (HIP 7.17.26416). Both
binaries were built without Nix, so neither is the pinned production package:

- Gufo: `cmake --preset release` (production flags, RelWithDebInfo) of commit
  `09c6149`, GCC 15.3.0 host compiler and ROCm AMD clang 24.0.0git for HIP
  (Nix pins clang 22). Binary SHA-256 `8911c533…`.
  The driver labels artifacts `nix-release`; that field is hard-coded.
- llama.cpp: ad-hoc ROCm build of `970b51ce` (Release, shared libraries,
  `GGML_HIP=ON`, `AMDGPU_TARGETS=gfx1151`, `GGML_HIP_NO_VMM`, `GGML_HIP_GRAPHS`,
  `GGML_HIP_MMQ_MFMA`, `GGML_CUDA_FA`, `GGML_NATIVE`), not a Nix pin.

power-profiles-daemon `performance` (amd_pstate; no ACPI platform profile)
for each sweep. Starting temperatures
Tctl 40 °C / GPU edge 39 °C; range 36–74 °C / 35–79 °C over 114 samples
(refreshes: 34–55 °C / 33–44 °C). Nothing else ran on the GPU.
Order: Gufo single-ar, multi-ar, memory; llama.cpp the same; then cold
loading on each. After the driver began hashing reasoning, multi-ar (three
cohorts per point) and then single-ar were re-run on both servers. Other
rows: one warmed sample.

Driver: `tools/bench/model-bench.py` with
[bench.json](artifacts/bench.json), which has no `speculative` section.
Gufo runs
`gufo serve llm --think off --max-pending-per-client 8` (`--think` has no
effect on Flint); llama-server runs `-ngl 999 -fa on --cache-reuse 0 --jinja
--reasoning off --cache-ram 0`, `-np C`, total `-c` covering every session.
Single-user prompt and cache counts match across servers at every depth
(131,072: 2053/130904 vs 2052/130905). Concurrency prepares every session's
pp2048 prompt before the timed tg128 cohort; all measured requests reuse the
prompt and generate 128 tokens.

Both servers return all 128 tokens as `reasoning_content`. Completion hashes
cover reasoning, NUL and content; all 63 Gufo concurrency completions match
its C1 output, which equals Gufo's single-user depth-0 completion.
llama.cpp's own C2–C8 greedy outputs vary across slots and cohorts (4–23
distinct hashes per point), and its depth-0 and prepared C1 completions
differ; cross-engine agreement is not a gate.

```sh
M=/path/to/flint-UD-Q4_K_XL.gguf
REF=/path/to/llama.cpp-970b51ce/build/bin/llama-server
B="python3 tools/bench/model-bench.py --model flint --gufo build/release/gufo --gguf $M"
$B run --target gufo --fresh --table single-ar,memory
$B run --target reference --reference-binary "$REF" --fresh --table single-ar,memory
$B run --target gufo --fresh --repetitions 3 --table multi-ar
$B run --target reference --reference-binary "$REF" --fresh --repetitions 3 --table multi-ar
$B run --target gufo --fresh --table loading --drop-caches "<evict and verify $M>"
$B run --target reference --reference-binary "$REF" --fresh --table loading --drop-caches "<evict and verify $M>"
uv run --no-project --with matplotlib $B render
```
